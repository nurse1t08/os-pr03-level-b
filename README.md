# Практическая работа № 3 — уровень B

**Тема:** дерево процессов, `fork`, `exec`, `wait`, зомби, сироты, copy-on-write.

## Запуск (Ubuntu с `/proc`)

```bash
bash run.sh
```

Отдельно:

```bash
python3 ptree.py
python3 runner.py --count 3 -- sleep 2
python3 zombie.py
python3 orphan.py
python3 cow_memory.py --mb 64
```

`ptree.py` читает `/proc/PID/status`, выбирает свой UID и строит дерево с `PID`, состоянием и `VmRSS`. `runner.py` запускает команду через `fork + execvp`, родитель вызывает `wait` и измеряет время каждого ребёнка.

`zombie.py` показывает `Z` с помощью `ps` до вызова `waitpid`, затем убирает запись процесса. Пример **реального проверочного запуска в Linux-контейнере** (PID каждый раз другой):

```text
$ python3 zombie.py
Ребёнок PID=1205 завершился, но ещё не был ожидаем:
    PID    PPID STAT CMD
   1205    1195 Z    [python3] <defunct>
waitpid вызван, zombie убран из таблицы процессов.
```
 `orphan.py` даёт родителю завершиться; ребёнок позже показывает новый `PPID` — его принимает PID 1 или ближайший назначенный subreaper (зависит от среды). После демонстрации ребёнок завершает работу сам.

`cow_memory.py` выделяет память, делает `fork` и сравнивает **RSS** и `Private_Dirty` до/после записи. При COW физические страницы сначала разделяются; запись создаёт частные копии. Важно: **RSS ребёнка может почти не измениться**, потому что совместно используемые страницы уже учитывались в его RSS; лучше всего COW виден по росту `Private_Dirty` / изменению PSS.

## Вывод

`fork` создаёт отдельный процесс, `exec` заменяет его программу, `wait` собирает код завершения. Зомби — уже завершившийся ребёнок без `wait`, сирота — живой процесс без прежнего родителя. Память после `fork` не копируется целиком до записи.
